Interfaces de Programación de Aplicaciones (API)

El puente de comunicación que conecta el Frontend con el Backend.

¿Qué es una API?

Una API es un conjunto de reglas que permite a distintas aplicaciones de software comunicarse entre sí. Funciona como un "mesero" que toma tu solicitud en el cliente, la lleva al servidor (la cocina) y te devuelve los datos que pediste.

APIs REST

Es la arquitectura más utilizada en la web. Permite interactuar con los datos utilizando los métodos estándar de HTTP:

  • GET: Obtener información.
  • POST: Crear nueva información.
  • PUT/PATCH: Actualizar datos.
  • DELETE: Borrar registros.

El Formato JSON

Es el lenguaje universal mediante el cual el Frontend y el Backend intercambian información en una API. Se basa en pares de clave y valor, siendo ligero y fácil de leer.

{
  "usuario": "dev_web",
  "rol": "admin"
}

Anatomía de una Petición a una API

Para consumir una API correctamente, tu código (Frontend) debe armar una petición que contenga las siguientes partes fundamentales:

1. Endpoint (La Ruta)

Es la URL exacta a la que te diriges para pedir un recurso específico.

2. Cabeceras (Headers)

Información oculta que viaja con tu petición (como el formato JSON esperado).

3. Cuerpo (Body)

El paquete de datos que envías (solo en métodos POST o PUT).

4. Códigos de Estado

Respuestas del servidor: 200 OK, 404 Not Found.

Ejemplo en Vivo: Fetch API

Veamos cómo funciona. Vamos a hacer una petición GET a una API pública (JSONPlaceholder) utilizando JavaScript para obtener los datos de un usuario ficticio y pintarlos en la tarjeta de la derecha.

fetch('https://jsonplaceholder.typicode.com/users/1')
  .then(response => response.json())
  .then(data => {
    // Aquí pintamos los datos en el HTML
    mostrarUsuario(data);
  });
